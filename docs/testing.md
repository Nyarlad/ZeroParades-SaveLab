# Test plan

Public tests use only data generated by `demo.synthetic_save`. No real or anonymized player file is committed.

| Area | Verification |
| --- | --- |
| Hash and codec | Public empty-message SpookyHash vector; framing boundary sizes; exact crypto roundtrip; both checksums |
| Malformed input | Truncation, corruption, unsupported versions/marker, trailing bytes, negative/oversized lengths, invalid UTF-8/JSON, duplicate properties and IDs, invalid flag types |
| Build gating | Unknown build remains inspect-only; edits fail closed |
| Model | Existing booleans only, unknown fields retained, irregular whitespace/Unicode, full semantic comparison |
| Presets | Each stage changes one flag only; wrong phase refused; unsupported executable descriptor rejected |
| Diff | Named flag IDs, categories and search, added/removed/null/type distinctions |
| File safety | Backups before writes, source stability, explicit consent, running-game refusal, exclusive export, neighboring files unchanged |
| Failure recovery | Backup write failure, rename/sharing failure, concurrent external update, corrupted target recovery, tampered backup refusal |
| GUI | Hidden Tk smoke with synthetic save list, search, both presets, export, diff filter, backup list |
| Frozen distribution | Standalone CLI decode and hidden GUI smoke without relying on a Python installation |

Run `python -m pytest -q`. GUI tests require Tk and a display; Windows CI provides this.
Linux CI runs core/CLI tests and skips the display test when no display is available.
The tests focus on integrity/refusal/recovery boundaries rather than widget styling or trivial accessors.

Private local integration checks are separate from CI and release contents. They must use backup copies, never modify active saves,
and verify byte-identical no-edit roundtrips plus one-flag diffs on the already observed before/after-handover snapshots.

The editor's prepared output was tested in the original game session for the first preset and subsequent historical-flag return.
The standalone editor itself still needs broader player testing across supported story configurations; no test suite executes the game engine.
